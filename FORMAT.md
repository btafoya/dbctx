# FORMAT.md

# dbctx Output Format Specification

**Format Version:** 1.0 (Draft)

## Purpose

This document specifies the canonical output formats generated by dbctx.

The document format version is independent of the application version.

------------------------------------------------------------------------

# Design Goals

-   Stable
-   Deterministic
-   Human-readable
-   Machine-readable
-   Backward compatible
-   Vendor neutral

------------------------------------------------------------------------

# Output Directory

``` text
.ai/dbctx/
├── schema.json
├── schema.md
├── metadata.json
├── relationships.json
├── graph.mmd
└── tables/
```

------------------------------------------------------------------------

# Common Metadata

Every JSON document begins with:

``` json
{
  "format": "dbctx.<type>",
  "format_version": "1.0",
  "generator": {
    "name": "dbctx",
    "version": "0.1.0"
  },
  "generated_at": "2026-01-01T00:00:00Z"
}
```

Required fields:

-   format
-   format_version
-   generator.name
-   generator.version
-   generated_at

------------------------------------------------------------------------

# schema.json

The canonical representation of the database.

## Root Object

``` text
schema
├── metadata
├── tables[]
├── views[]
└── relationships[]
```

## Database Metadata

Fields:

-   database
-   engine
-   engine_version
-   default_charset
-   default_collation

## Table

Required:

-   name
-   engine
-   charset
-   collation
-   comment
-   columns
-   indexes
-   foreign_keys

Optional:

-   analysis
-   ai

## Column

Required:

-   name
-   ordinal_position
-   data_type
-   full_type
-   nullable
-   default
-   auto_increment
-   primary_key
-   unique
-   comment

Optional:

-   generated
-   expression

## Index

Fields:

-   name
-   unique
-   columns\[\]
-   index_type

## Foreign Key

Fields:

-   name
-   columns\[\]
-   referenced_table
-   referenced_columns\[\]
-   on_update
-   on_delete

------------------------------------------------------------------------

# relationships.json

Contains only relationship information.

``` text
relationships[]
    from_table
    from_columns[]
    to_table
    to_columns[]
    constraint
```

Tables are sorted alphabetically.

Relationships are sorted by:

1.  from_table
2.  to_table
3.  constraint

------------------------------------------------------------------------

# metadata.json

Contains project-level information.

Example fields:

-   database
-   engine
-   engine_version
-   table_count
-   view_count
-   foreign_key_count
-   generated_at

------------------------------------------------------------------------

# schema.md

Goals:

-   Compact
-   Readable
-   Token efficient

Structure:

``` text
# Database

## Summary

## Tables

### customers

Columns

Indexes

Relationships
```

Markdown is intended for humans and AI agents.

------------------------------------------------------------------------

# graph.mmd

Mermaid ER diagram.

Requirements:

-   Deterministic ordering
-   Stable identifiers
-   Valid Mermaid syntax

------------------------------------------------------------------------

# tables/

Each table is exported separately.

Example:

``` text
tables/
    customers.json
    orders.json
```

Each file contains:

-   metadata
-   one table definition

------------------------------------------------------------------------

# Ordering Rules

Deterministic ordering is REQUIRED.

Sort:

-   tables
-   columns
-   indexes
-   relationships
-   views

Alphabetically unless database ordinal position is semantically
meaningful.

------------------------------------------------------------------------

# Null Values

Use explicit JSON null.

Do not omit fields solely because values are null.

Optional sections may be omitted only when disabled.

------------------------------------------------------------------------

# Optional Sections

Enabled with flags.

## --analyze

Adds:

``` json
{
  "analysis": {
    "kind": "lookup_table",
    "confidence": 1.0,
    "evidence": [
      "deterministic_rule"
    ]
  }
}
```

Analysis must be deterministic.

------------------------------------------------------------------------

## --llm

Adds:

``` json
{
  "ai": {
    "generated": true,
    "confidence": 0.91,
    "summary": "...",
    "notes": []
  }
}
```

Requirements:

-   Clearly labeled
-   Never overwrite facts
-   Easily removable

------------------------------------------------------------------------

# Compatibility Rules

Readers MUST ignore unknown fields.

Writers MUST preserve format_version.

Breaking structural changes require a new major format version.

------------------------------------------------------------------------

# File Naming

Lowercase.

Stable.

No timestamps in filenames.

------------------------------------------------------------------------

# Encoding

-   UTF-8
-   Unix line endings
-   Pretty-printed JSON (2 spaces)
-   Trailing newline

------------------------------------------------------------------------

# Checksums (Future)

Future versions may include SHA-256 manifests for generated artifacts.

------------------------------------------------------------------------

# Validation

Generated artifacts must validate against the published JSON Schema for
their format version.

------------------------------------------------------------------------

# Canonical Source

The canonical source for all output formats is the internal schema model
defined by the library.

Exporters must not query the database directly or derive facts outside
the canonical model.
